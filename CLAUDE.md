Контекст
- glint (github.com/aiseeq/glint) — универсальный статический анализатор Go/TypeScript. Единственный remote — `origin` (GitHub), trunk — `main`.
- Правила разложены по категориям (architecture, duplication, patterns, typesafety, security, deadcode, naming, documentation). Авторитетный список — `glint rules`; README вторичен, количество правил в тексте не фиксировать.
- Single-pass: файлы читаются и парсятся один раз, AST-кэш, параллельное выполнение. YAML-конфиг с наследованием и per-rule exceptions, autofix для части правил, вывод console/JSON/summary.
- Потребители — закрытые проекты автора. Новые правила и фиксы — TDD-репро с реальных находок. Находки на проектах-потребителях после правки glint чинят их агенты: в их код отсюда не ходить.
- ПУБЛИЧНАЯ РЕПА — БЕЗ ВНУТРЕННИХ ИМЁН: в коде, тестах, комментариях и сообщениях коммитов запрещены имена закрытых проектов и работодателя, номера внутренних тикетов (SI-NNN и подобные), имена провайдеров/интеграций закрытых проектов, их внутренние функции и пути. Репро переписывать на синтетические имена (projectA/payprov-стиль); какую багу ловит правило, документирует его тест, а не коммит-сообщение. Перед коммитом проверить diff и текст сообщения на эти утечки.
- Утечка в выпущенной истории: имена и данные закрытых проектов работодателя - вычищаются переписыванием истории (решение автора 28.10: «"оставить" - кроме прям рабочих проектов»); остальное (имена функций, личные репо автора) - не утечка, историю ради этого не переписывать и не предлагать. Находку назвать одной строкой как факт.

Сборка и проверки
- `graft build`; `graft install` — атомарная установка в ~/bin. После изменения правил переустановить, иначе потребители не увидят новую версию. В бинарь вшивается `graft version --describe` (теги `v*`, `version.mode: git-tag`), её печатает `glint --version`.
- `graft test | all` (fmt-check vet lint test test-race) | `self-check` (glint на самом себе). После правки правила — тесты и self-check.
- Гейт `graft commit` — `smoke` (fmt-check, vet, test-short). Полный прогон — `graft all`. Тег релиза — `graft release`.

Правила анализатора
- Ложное срабатывание чинить в правиле: TDD-репро (красный тест с синтетическим аналогом реального кода) → фикс правила. Suppress в целевом проекте — только для осознанного дизайна, не вместо фикса правила.
- У правил много общей инфраструктуры (core.LineSuppresses, реестр, AST-хелперы). Документация — go/ast, go/types, tree-sitter.
- Правила лежат по группам `pkg/rules/patterns/<группа>/`, общий слой — `pkg/rules/patterns/internal/patternkit`, хелперы тестов — `internal/patterntest`.
- Path-sensitive правила писать на generic `patternkit.FlowWalker` (pkg/rules/patterns/internal/patternkit/flow_walker.go), а не на собственном обходе потока управления.
- Список путей в flow-правилах объединять только через `patternkit.JoinFlowPaths` (там же, flow_paths.go) с ключом пути: `append(left, right...)` даёт 2^N путей и съедает память на больших функциях.
- Поведение правила проверять запуском на тест-кейсе и `glint rules`, а не по README и комментариям.
- Типизированная загрузка идёт с `Tests: false`. При `packages.Load(Tests:true)` пакет приходит вариантами (`P`, `P [P.test]`, `P.test`, `P_test [P.test]`) с разными `*types.Named`. Если сигнатура метода интерфейса упоминает именованный тип пакета, `types.Implements` между вариантами даёт false, и живой интерфейс выглядит мёртвым. Поэтому проверять каждый вариант, а реализации сводить по позиции объявления.
- Выход майнинга истории потребителя (batch-*.tsv, *.jsonl, манифесты) сразу класть в `~/.local/share/glint-history/<проект>/`, не только в scratchpad: так уже терялись данные. Майнинг личного sc2go — без Jira и ворклогов (план и итог в чате и коммитах); его неуниверсальные находки — в `~/git/sc2go/cmd/sc2lint` в той же сессии.
- Правка, меняющая охват правила (новое правило, снятое освобождение файла или пути, новое допущение), — до `graft install` прогон `bin/glint check -r <rule>` из корня каждого потребителя (проекты с `.glint.yaml` в `~/work` и `~/git`, кроме замороженных — список в скилле `glint-gap`, шаг 4) с его конфигом и разбор каждой находки: ложная — назад к TDD-репро, верная — агенту потребителя. Установка сразу роняет гейт каждого потребителя на новой находке.
