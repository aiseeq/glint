Контекст
- glint (github.com/aiseeq/glint) — универсальный статический анализатор Go/TypeScript. Единственный remote — `origin` (GitHub), trunk — `main`.
- Правила разложены по категориям (architecture, duplication, patterns, typesafety, security, deadcode, naming, documentation). Авторитетный список — `glint rules`; README вторичен, количество правил в тексте не фиксировать.
- Потребители — закрытые проекты автора. Новые правила и фиксы — TDD-репро с реальных находок. Находки на проектах-потребителях после правки glint чинят их агенты: в их код отсюда не ходить.
- ПУБЛИЧНАЯ РЕПА — БЕЗ ВНУТРЕННИХ ИМЁН: в коде, тестах, комментариях и сообщениях коммитов запрещены имена закрытых проектов и работодателя, номера внутренних тикетов (SI-NNN и подобные), имена провайдеров/интеграций закрытых проектов, их внутренние функции и пути. Репро переписывать на синтетические имена (projectA/payprov-стиль); какую багу ловит правило, документирует его тест, а не коммит-сообщение. Перед коммитом проверить diff и текст сообщения на эти утечки.
- Утечка в выпущенной истории: имена и данные закрытых проектов работодателя - вычищаются переписыванием истории (решение автора 28.10: «"оставить" - кроме прям рабочих проектов»); остальное (имена функций, личные репо автора) - не утечка, историю ради этого не переписывать и не предлагать.

Сборка и проверки
- После изменения правил переустановить, иначе потребители не увидят новую версию. В бинарь вшивается `graft version --describe` (теги `v*`, `version.mode: git-tag`), её печатает `glint --version`.
- После правки правила — тесты и self-check.
- Тег релиза ставит `graft install` на main (HEAD без тега); ручной `graft release` — только для `--minor`/`--major`.

Правила анализатора
- Ложное срабатывание чинить в правиле: TDD-репро (красный тест с синтетическим аналогом реального кода) → фикс правила.
- Path-sensitive правила писать на generic `patternkit.FlowWalker` (pkg/rules/patterns/internal/patternkit/flow_walker.go), а не на собственном обходе потока управления.
- Список путей в flow-правилах объединять только через `patternkit.JoinFlowPaths` (там же, flow_paths.go) с ключом пути: `append(left, right...)` даёт 2^N путей и съедает память на больших функциях.
- При `packages.Load(Tests:true)` пакет приходит вариантами (`P`, `P [P.test]`, `P.test`, `P_test [P.test]`) с разными `*types.Named`. Если сигнатура метода интерфейса упоминает именованный тип пакета, `types.Implements` между вариантами даёт false, и живой интерфейс выглядит мёртвым. Поэтому проверять каждый вариант, а реализации сводить по позиции объявления.
- Выход майнинга истории потребителя (batch-*.tsv, *.jsonl, манифесты) сразу класть в `~/.local/share/glint-history/<проект>/`, не только в scratchpad: так уже терялись данные.
- Правка, меняющая охват правила (новое правило, снятое освобождение файла или пути, новое допущение), — до `graft install` `graft consumers` и разбор каждой новой находки: ложная — назад к TDD-репро, верная — агенту потребителя. Установка сразу роняет гейт каждого потребителя на новой находке. Правило с десятками ложных на живом проекте не ставить.
  Зачем: релиз glint не роняет гейты всех проектов ложными находками
