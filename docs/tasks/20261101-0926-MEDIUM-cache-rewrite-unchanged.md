# Result cache rewrites the whole root file on every run, also when nothing changed

Статус: открыт

## Вход
- Лид 01.11 09:22 CET (тикет лида /home/aisee/docs/tasks/20261029-1711-MEDIUM-snapper-cleanup-freeze.md): ~/.cache/glint/results — 438 МБ записи в /home за 45 минут (06:30–07:15), фризы snapper.
- Замер 01.11 09:24 CET: в results 26 файлов, за последний час переписаны все, 456 МБ. Файл корня — 24–62 МБ (самый большой — 62 МБ на корне в 2071 файл). save() (cmd/glint/cache.go) кодирует и переписывает весь файл корня на каждом прогоне, даже когда все файлы и проектные правила взяты из кэша.
- Кэш вынесен в отдельный subvolume (снапшоты /home его больше не видят), но запись на диск остаётся.

## Что сделать
1. Прогон, который ничего не изменил в записи (все файлы и правила из кэша, тот же набор файлов), не переписывает файл: только обновляет mtime (prune считает по нему LRU и grace).
2. Разобрать, почему файл корня весит 24–62 МБ: что в нём занимает место (находки с полными полями, RuleState индексов, хэши), и можно ли хранить меньше без потери корректности.

## Приёмка
- Два прогона подряд `glint check .` без изменений: второй не меняет содержимое и inode файла кэша (stat до и после), mtime обновлён.
- Прогон с правкой одного файла переписывает запись, находки равны `--no-cache`.
- Размер файла кэша на самом большом корне — было/стало.
