# clock-bypass с clock_package пропускает пакеты main целиком

Статус: в работе
Исполнитель: glint-master

## Вход
- Запрос: мастер потребителя А 30.10 ~07:50 CET, находка его ревью.
- clock-bypass с `clock_package` пропускает пакеты `main` целиком: `pkg/rules/patterns/timerules/clock_bypass.go:71` (`pkg.Package.Name == "main"`) и `:308` (`productionClockFiles`).
- Пропущено: подкоманда бинаря (`package main`) передаёт `time.Now().UTC()` в доменный сервис как «сейчас»; утилита разработчика в отдельном `cmd/` тоже идёт мимо часов проекта.
- Исключение main пришло с первой версией правила (72c1bb1), причина не записана; тесты закрепляют его как поведение (TestClockBypass… с `command/main.go`).

## Что сделать
1. С `clock_package`: пакеты `main` модуля, которому принадлежит `clock_package`, проверяются, как остальные.
2. Не находка — настройка часов в точке входа: стандартное чтение часов, переданное аргументом в функцию пакета часов (в том числе внутри func literal) или присвоенное его переменной.
3. Пакеты другого модуля (отдельный `go.mod` без часов проекта) — не находка: у них своё время.
4. Без `clock_package` (режим счёта) — поведение прежнее.

## Приёмка
- Тесты брифа зелёные, `graft all` 0.
- Копия потребителя А (scratchpad мастера, `consumer-a-main`): 6 находок в двух main-пакетах модуля часов (подкоманда бинаря — 1, утилита разработчика — 5); в отдельном модуле монитора — 0.
- `graft consumers -- -r clock-bypass`: каждая новая находка разобрана.
- Проверка — мастер потребителя А.
